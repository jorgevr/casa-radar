## Systematic matrix (matrix5.py)

The matrix covers these dimensions:
- Columns: price, area_m2, exterior, property_type, location_text, url, title, municipality/zone and
  new_build.
- Stored value: null or non-null.
- Recorded origin: none, alert, idealista_api, manual, csv or user. For new_build it is also crossed
  with `new_build_origin` (null, email, category or user).
- Sighting: supplies the value or does not.

Results for a non-null stored value:
- No origin, alert or idealista_api:
  - When the sighting supplies a value, the alert value wins and is labelled `alert` (price and
    attributes).
  - url and title with an idealista_api origin are kept. That was accepted in r3.
  - When the sighting supplies nothing, the stored value and its label are kept (FR-011).
- manual/csv:
  - The value is never written. A differing value raises
    `la alerta dice 650.000 € / 150 m² / sí / … (27/10/2026)`, and the label is kept (FR-023).
  - A price or new_build that is not stated raises no flag.
- `user` is not a `field_sources` value in data-model and is treated as unprotected. The exception is
  `new_build_origin = user`, which is always kept: the value is kept, and the flag is raised only when
  the stored value is not 1.

Results for a null stored value: the alert fills it, or it stays null with no label. An alert never
writes null over a known value.

Price, history and dates (also covered by T022):
- A same-day tie takes the higher price and raises the conflict flag.
- `alert_previous` comes before the same-day `alert` row.
- The mismatch flag compares against the price of the latest earlier day.
- An older drop goes to history only.
- `published_at` is the earliest `new_listing` date.
- `price_updated_at` is the date of the latest change, or the drop date for a listing created by a
  drop alone.
- A user-owned price keeps `price_updated_at`, and no alert rows are written for it.

`first_seen`/`last_seen` are the minimum and maximum sighting day. `alert_flags` is rebuilt on every
derivation.

SQL: every column written exists in app/db.py (SCHEMA/ADDED_COLUMNS). The history rebuild deletes only
`alert`/`alert_previous` rows. T027 matches its handoff.

Constitution: no rates or thresholds as literals, no network, no secrets, no new dependency. Test
expectations are hand-derived.
